# Nimbus cost-review product research — September 26, 2026

Cloud cost work is recurring: teams need cost allocation, context-rich recommendations, budgets, anomaly detection, review workflows, and safe action boundaries. Nimbus's live path gathers paginated AWS inventory, hourly EC2 CPU/network metrics, and service-level Cost Explorer totals through TrueForge; the native daily schedule records a bounded local baseline keyed by exact account and region and writes an inspectable TrueForge session. Cross-run comparisons use only overlapping complete dates and are reported as changes, not anomaly verdicts. It does not provide calibrated anomaly detection or alerting. The synthetic scanner cannot stand in for a bill or connected-account telemetry. A prior AWS Core check reported resource-level Cost Explorer access disabled on that separate account, so those service totals cannot be used as per-resource costs.

## Product direction

The immediate product is a **human-operated evidence review**. A reviewer requests live evidence; the agent labels scope and gaps, validates the response, and prioritizes what to investigate. It may add one fixed review marker to an exact unattached EBS volume after rechecking account/state and pausing for TrueForge approval. A separate destructive demo tool is now implemented in source but remains disabled unless an operator allowlists one dedicated, tagged, encrypted 1 GiB gp3 demo volume. Its live approval/denial path is not yet verified. It must not claim savings or safe deletion from inventory state or service totals.

The native TrueForge schedule is configured to run daily, retaining each review as a TrueForge session and updating a local bounded baseline keyed to account and region. Its first scheduled run is still pending. The combined MCP tool implements comparisons across overlapping complete dates and surfaces identity/coverage/freshness limits. Next work is validation across repeated scheduled runs, safer shared backup/storage, and evidence-linked alert delivery. Establish baseline quality before anomaly labels. Keep AWS writes separate, explicitly requested, freshly revalidated, and individually approved; never run unattended cleanup.

## TrueForge hackathon iteration — 2026-09-26

Round 1 established a real TrueForge run baseline and uncovered an unresolved identity mismatch: Nimbus saw zero EC2 instances while the prior AWS Core inspection found one instance in `us-east-1`. The Round 2 live run reduced observed TrueForge trace calls from 11 to 3 and Nimbus AWS reads from 3 to 1. AWS Core and local Nimbus are authenticated to different AWS accounts, so Nimbus must not make account-complete claims until its identity is aligned. See the [Round 1 baseline](../benchmarks/rounds/2026-09-26-round-1.md) and [Round 2 live evaluation](../benchmarks/rounds/2026-09-26-round-2-live.md).

The first improvement round reuses the Apache-2.0 AWS Agent Toolkit for AWS billing skill by reference and adds Nimbus's own reusable TrueForge Git skill, structured MCP output contracts, a single-call evidence bundle, and deterministic service/day aggregation. The upstream implementation details, compatibility limits, auth boundary, and citations are documented in [`research/aws-agent-toolkit-reuse-and-trueforge-fit-2026-09-26.md`](../../research/aws-agent-toolkit-reuse-and-trueforge-fit-2026-09-26.md). The AWS toolkit plugin is source-available; its AWS MCP Server target is managed, not itself the open-source implementation.

Benchmarks are mandatory for each iteration: [`benchmarks/README.md`](../benchmarks/README.md) defines the repeatable live-run and local microbenchmark protocol. The Round 2 live run is complete: one observed run reduced trace tool/runtime calls from 11 to 3 and AWS evidence reads from 3 to 1. This is one run per round, not a stable speed claim. The local microbenchmark measures only deterministic aggregation, not end-to-end model/AWS performance. Repeat comparable live runs after the account scope is selected and report model, provider, identity, and date window.

Beyond MCP access, Nimbus contributes identity/scope reconciliation, bounded evidence collection, local cross-run state, deterministic analysis, a dated report and native Generative UI inside the TrueForge session, freshness/coverage qualification, repeatable evaluation, and human follow-up. The daily schedule is active on the selected local AWS profile, with its first execution still pending; TrueForge and the Nimbus MCP server must be available, and runs may incur model/provider and Cost Explorer charges. Future rounds should validate the baseline across multiple schedule ticks, improve backup/retention, and establish calibrated anomaly triage; leave external notifications and AWS remediation off until their permissions and reliability are measured.

Round 2 local benchmark result: the production aggregation routine passed seven 1,000-iteration runs on a 42-row fixture; median-of-run-medians is 0.0060 ms. Round 3 adds an independently checked baseline-comparison microbenchmark. Across five fresh processes (1,000 iterations per function per process), median process medians were 0.0114 ms for daily aggregation and 0.0265 ms for baseline comparison; medians of process p95 values were 0.0239 and 0.0526 ms. This measures local deterministic functions only, not end-to-end performance. See [`benchmarks/rounds/2026-09-26-round-2-local.md`](../benchmarks/rounds/2026-09-26-round-2-local.md) and [`benchmarks/rounds/2026-09-26-round-3-local.md`](../benchmarks/rounds/2026-09-26-round-3-local.md).

The Round 3 safety improvement adds a `DeleteVolume` MCP action constrained to one operator-configured demo volume, exact disposable tags, encrypted 1 GiB gp3 shape, available state, zero attachments, caller/account checks, and an explicit TrueForge approval selector. The tool defaults closed and does not provision the target. It has not been live-enabled or used; the product still needs a controlled approval/denial/revalidation demonstration. A scheduled run must never call it.

The baseline store now caps history at 90 records per exact account/region and 1,000 records total, writes the temporary snapshot file with mode `0600`, and retains newest records under both caps. Automated tests cover the global cap and restrictive file mode. This is local private state, not durable shared monitoring storage.
