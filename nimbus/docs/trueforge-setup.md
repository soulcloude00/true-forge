# Nimbus on TrueForge: runbook

This is a local integration branch descended from the separate pre-event prototype. The event page at https://hackculture.io/hackathons/agents-that-act states that projects must be built during the event and pre-built projects are not eligible. Submission of reused code remains an organizer decision, not established by this project. Keep the local TrueForge server on localhost. The hosted preview cannot reach a user's localhost agent.

1. Install Node.js >=22.14, `npm ci`, then `npm run mcp` in one terminal. Use `npm run mcp:smoke` to verify exactly two read-only tools. The custom Streamable HTTP MCP endpoint is `http://127.0.0.1:8792/mcp`; it exposes only read-only AWS inventory and service-level Cost Explorer calls. Never enter AWS credentials in the web page or chat; use your local AWS credential chain and a read-only IAM role. AWS calls require account permissions for STS GetCallerIdentity, EC2 Describe*, ELB DescribeLoadBalancers, and Cost Explorer GetCostAndUsage. Region defaults to AWS_REGION or us-east-1. Inventory follows service pagination but caps collection at 20 pages per service; any cap reached is returned in `coverage.truncatedServices`.
2. Run `npx @truefoundry/trueforge@0.2.1` in another terminal. Open `http://localhost:8790` and configure a model provider in Settings. For sandboxed code execution, TrueForge presently requires a Daytona sandbox provider and a Daytona API key in Settings; merely toggling sandbox on does not configure the provider. Keep both services local, do not expose the no-login server publicly.
3. In TrueForge Settings > Connectors, add the custom MCP URL above as a no-auth local connector named `nimbus-aws-readonly`. Verify the connector sees the two read tools. Create a saved agent named `nimbus-cost-agent` with `npm run agent:install -- provider/model-name` after configuring the selected model, or use the spec in `trueforge-agent-spec.json` in the UI/API. Run `npm run verify:setup` to check both local endpoints. The spec grants only the two read-only tools and enables sandbox; no AWS write tool is exposed, so reads run without unnecessary approval pauses. If a write tool is ever added, require explicit TrueForge approval for that exact tool and test the approval flow before enabling it. If the server rejects the agent because the model, connector, or sandbox isn't configured, fix Settings first.
4. `npm run dev` serves the React front end. Open it on the same laptop as TrueForge. The Nimbus landing/report remains a labeled synthetic/local-input preview; the Agent panel links to the bundled TrueForge chat UI running on the same laptop. Select the saved nimbus-cost-agent there. The local server already ships the official TrueForge chat UI; bundling the separate React UI SDK into Nimbus exceeded the small build host memory limit, so this lightweight page links to the same locally running agent UI. For a genuine demo, inspect the live TrueForge turn and its MCP tool response; do not claim a live AWS scan from the offline fixture report.

No AWS mutation tool is exposed. Approve in the legacy report changes only local planning state, not an AWS resource. If a delete or stop tool is added later, mark it destructive in MCP and list it explicitly in `require_approval_for_tools` before any use. Never use the local no-login server as a public internet deployment. These points reflect https://trueforge.dev/quickstart , https://trueforge.dev/mcp-servers , https://trueforge.dev/sandbox , and https://trueforge.dev/create-agent/overview .
